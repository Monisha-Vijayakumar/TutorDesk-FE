## Project

TutorDesk is a tuition-center dashboard (MERN, portfolio/POC). An admin (tutor) manages students, batches and fees; students/parents get a read-only portal. **Attendance is removed for now** (2026-11-21).

- This repo: **`tutordesk-fe`** — React frontend, deployed to Vercel.
- Sibling repo: **`tutordesk-be`** — Node/Express + MongoDB API, deployed to Render/Railway.
- FE talks to BE only over HTTP via `VITE_API_BASE_URL` (local: `http://localhost:5000/api`), with `withCredentials: true` (JWT lives in an httpOnly cookie).
- Full spec: [REQUIREMENTS.md](REQUIREMENTS.md). The API contract (Section 7) is shared with the BE repo — if it changes, update it in both repos.

## Current scope / priorities

- Build **Admin pages first**. Student/Parent pages (REQUIREMENTS §5.3) are **on hold** until admin pages are done.
- Build order follows REQUIREMENTS §10 milestones: setup → auth & roles → students → batch management → fees → dashboard → student portal → notifications → polish → deploy.
- Out of scope for core: payment gateway, SMS / automated WhatsApp, file uploads, real-time, multi-tenant, **attendance** (removed 2026-11-21 — no page, nav item, route, endpoints, types or stats). **Batches exist only on the Batch Management page** (back since 2026-11-21, REQUIREMENTS §4.3) — no batch fields/columns/filters on Students or Fees; no batch subjects, schedules, clash checks or one-batch-per-student rule.

### Auth flow
- On load, `App` dispatches `fetchCurrentUser` (`GET /auth/me`) to restore the session from the cookie. `auth.isSessionChecked` starts `false` and becomes `true` when that check finishes (success or failure); guards show a loader until then so a logged-in user isn't sent to `/login` on refresh. No StrictMode guard — the double call in dev is accepted.
- The login thunk sets `auth.user`; logout clears it even if the request fails and lands on the **landing page** (FR-4); a 401 (session expired) goes to `/login` with the toast instead. There is no signup: the single ADMIN is created by the BE seeder, students by the admin.
- **Forced password change (FR-9g):** while `user.mustChangePassword` is true, `getPathAfterLogin` and `ProtectedRoute` send the user to `getRequiredPasswordChangePath(user)` (admin: `/admin/settings/password`; students: none until the student portal) and every other page redirects there. `changePassword.fulfilled` clears the flag.
- After login: go back to the page they were trying to open (`LoginRedirectState.requestedPath`) if it belongs to their role, otherwise to `getHomePathForRole(role)`.
- New protected pages: add the path to `PATHS`, then add a **lazy** route under the `/admin` (or `/student`) branch in `router.tsx` using that constant (NFR-27) — never import a portal page statically.
- Read the user with `useAppSelector(selectCurrentUser)`, not inline selectors.

Target structure (REQUIREMENTS §9.1): `components/`, `layouts/` (AdminLayout, StudentLayout, PublicLayout), `pages/{public,admin,student}/`, `store/`, `api/` (axios instance, services, endpoints, API interfaces, API messages), `hooks/`, `utils/`, `routes/` (route config + guards).

## Conventions & key rules

### Code quality (mandatory — REQUIREMENTS NFR-10 to NFR-16)
- **Forms: sanitize → validate → build payload** (NFR-16). `sanitizeFormValues(values, ["password", ...])`, then validate with `validator` methods called directly (no manual regexes/checks), then build the payload from sanitized values with inline chaining for field-specific tweaks (`email.toLowerCase()`). Never alter passwords; never HTML-escape input.
- **Name/place fields letters only** (NFR-17), in every form: person name, city, state → `isAlpha(value, ALPHA_LOCALE, ALPHA_WITH_SPACES_OPTIONS)`; center name, branch → `ALPHA_WITH_PUNCTUATION_OPTIONS` (also `.` `'` `-`). Ends trimmed, middle spaces kept. Optional fields only when filled.
- **Arrow functions everywhere** (components, hooks, utils, services, selectors, handlers): `export const HomePage = () => { ... }`, `const handleSubmit = async (...): Promise<void> => { ... }`. No `function` declarations; define before use (no hoisting). Leave generated `src/components/ui/` files alone.
- **Group imports**: one import statement per module with named imports (`import { a, b } from "x"`), not one line per function. Exception: `validator`, which is imported per function to keep the bundle small.
- **Interfaces** (NFR-19): API shapes (models, payloads, responses, API errors) → `src/api/interfaces/<feature>.ts`; everything else (form values, state, hook results, component props) → `src/interfaces/<feature>.ts`. Import with `import type`; no inline interfaces anywhere.
- **API code in `src/api/`** (NFR-20): endpoints, `ERROR_MESSAGES`, `SUCCESS_MESSAGES`, `services/` (`apiClient.ts` + `<feature>Service.ts`), `interfaces/`. New API things go here.
- **Validation messages** (NFR-21): all of them, now and in future, in `VALIDATION_MESSAGES` in `src/constants/validation.ts`.
- **No validation in components** (NFR-18): components keep only core logic (state, handlers, dispatch, navigation, toasts, JSX). Validation goes in `src/utils/<feature>Validation.ts`; form value types in `src/interfaces/`. Components never import `validator` or `VALIDATION_MESSAGES`.
- **XSS** (NFR-22): render text with plain JSX; HTML strings only via `<SafeHtml html={...} />` (DOMPurify). Never `dangerouslySetInnerHTML` directly; never DOMPurify/HTML-escape form input before sending.
- **No thin wrappers** around library methods — call them directly. A util must add real logic and be reused.
- **Write it like a developer would, not like generated code**: plain, direct code; no over-engineering, no filler JSDoc on obvious things, no boilerplate comments.
- **API endpoints**: every URL comes from `API_ENDPOINTS` in `src/api/apiEndpoints.ts` (id paths are functions, e.g. `API_ENDPOINTS.STUDENTS.DETAILS(studentId)`). Never inline a URL string in a service.
- **Meaningful names only**, named by functionality: `PascalCase` components/types, `camelCase` functions/variables (functions start with a verb, booleans `is/has/can`, handlers `handleX`, props `onX`), `use*` hooks, `UPPER_SNAKE_CASE` constants. Component file name = component name.
- **Type everything**: named props type per component (`XxxProps`), typed function params, return types on every function except React components (components have no `: ReactElement`), all interfaces in `src/interfaces/` (NFR-19). No `any`.
- **Readable for a mid-level dev**: small single-purpose components/functions, early returns, no clever one-liners, comments only for the non-obvious *why*.
- **Reuse**: anything used in 2+ places → shared component (`src/components/`) or hook (`src/hooks/`).
- **Constants**: repeated values (statuses, roles, limits, labels, messages) defined once and exported from `src/constants/` (or a feature `constants.ts`); no duplicated literals.

- Money is handled as **integers in the smallest unit** (paise) — format for display only, never use floats.
- Fee statuses: Paid / Partial / Pending / Overdue. Use a shared `StatusBadge`.
- Every data page needs loading (skeleton), empty, and error states.
- **Consistent design (NFR-24) on every existing and new page.** Required form fields: pass `isRequired` to `FormField` / `FormSelectField` / `FormCheckboxGroup` (red `*` + `aria-required`) — login included. Never write "(optional)" in a label — optional fields simply have no marker. Every form with required fields shows `<RequiredFieldsNote />` at the top (already inside `AuthFormCard`). Filters/search are never marked. Build pages from the shared components (`PageHeader`, `EmptyState`, `DataTable`, `ConfirmDialog`, `StatusBadge`, `Sheet` forms) with the same control heights (40px phones / 36px from `md`) and wording.
- **Responsive on all major devices** (NFR-23) — every existing and future page: 320px fallback, 360px phones (primary), flip/fold phones (incl. short landscape), tablets, large 2560px+ desktops. ### Data fetching & module architecture (NFR-26 — same for every module)
- **Follow the Auth module.** Per feature: API types + `<Feature>Service` interface (`src/api/interfaces/<feature>.ts`) → `src/api/services/<feature>Service.ts` (real axios calls; mock twin in `src/api/mocks/`) → `src/store/<feature>Slice.ts` (`createAsyncThunk` thunks, reducers, `select…` selectors; registered in `store/index.ts`; names in `constants/actionTypes.ts`) → pages/components with `useAppDispatch` / `useAppSelector`. Components never call services or axios directly. State/props types in `src/interfaces/<feature>.ts`.
- **Every thunk** catches and returns `rejectWithValue(getApiError(error, ERROR_MESSAGES.<ACTION>_FAILED, optionalStatusMessages))` (NFR-25). Components check `thunk.fulfilled.match(result)` / `.rejected.match(result)`, take `result.payload ?? getApiError(result.error)`, toast `apiError.message`, branch on `hasApiErrorStatus(apiError, HTTP_STATUS.X)` and map field errors with `getFormErrorsFromApi` / `getStudentFormErrorsFromApi`. Don't add per-module status handling.
- **401:** handled once in `authSlice` (matcher on rejected-with-value actions): user cleared → `ProtectedRoute` → login page shows the session-expired toast (`SESSION_EXPIRED_TOAST_ID`). Don't build another auth mechanism.
- **List pages (Students, Batch Management, Fees):** `usePaymentSearchFilters` returns memoised `searchParams` (Fees adds `month` in a `useMemo`); the page loads in `useEffect(() => { const request = dispatch(fetchX(params)); return () => request.abort() }, [dispatch, params])`; slices store `listRequestId` and ignore responses of older requests; aborted requests aren't errors. `DataTable` gets `isLoading={!hasLoadedList}` and `isFetching={isListLoading}`; the error state shows `listError` (from `getApiError`) with Try again. After create/update/delete (and on a 404 for a record deleted elsewhere) the page reloads the list (`reloadStudents` / `reloadFees` via the sheet/dialog callbacks).
- **Detail views that switch between records** (Payment History, batch View/Edit): the slice clears the data when a different id starts loading and the selector takes the id (`selectPaymentHistory(state, studentId)`, `selectBatchDetails(state, batchId)`), so another record's data never shows. Batch details are always cleared when loading starts and when the sheet finishes closing, so the edit form never starts from outdated values.
- **Picking records of another module in a form** (students in the batch form): add a `fetch<X>Options` thunk + `options…` state to that module's slice, calling its existing service — never a second API or a copy of its state in the other module.
- **Duplicate prevention:** forms keep a local `isSubmitting` (as in LoginPage) and disable Save; reminders use `sendingReminderFeeIds` in `feeSlice` (button disabled + thunk `condition`).
- **Shared list UI:** `PaymentSearchFilters` (page extras such as the month picker in `leadingFilter`, changing them calls `goToFirstPage`), `get<Feature>TableColumns(options)` memoised in the page, `RowActionButton` (`isDisabled`), `<Feature>MobileCard` for narrow content (table from `@4xl`). Search is debounced (`useDebouncedValue`, 300 ms).
- Not used: RTK Query (replaced 2026-11-20 by the Auth pattern), React Query, redux-saga; React Hook Form + Zod (forms use `useForm` + `validator`, NFR-16); date-picker libraries (native `<input type="date">`).
